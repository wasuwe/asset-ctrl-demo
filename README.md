# Asset Ctrl

ทะเบียนอุปกรณ์ IT และงานซ่อมของโรงงาน เขียนด้วย ASP.NET Web Forms (.NET Framework 4.8) และ PostgreSQL

Demo: https://asset-ctrl-demo.vercel.app

Demo ใช้ข้อมูลตัวอย่างที่สร้างขึ้นเอง ไม่มีฐานข้อมูลอยู่เบื้องหลัง และสิ่งที่แก้จะหายเมื่อรีเฟรชหน้า

| บทบาท | รหัสพนักงาน | รหัสผ่าน |
|---|---|---|
| Admin (ทีม IT) | `EMP0007` | ใส่อะไรก็ได้ |
| User (พนักงานแผนก) | `DEMO01` | ใส่อะไรก็ได้ |

ก่อนเข้าสู่ระบบ หน้าแรกเป็นรายการอุปกรณ์ทุก Work Center แบบดูอย่างเดียว ค้นหาและกรองได้ ส่วนตัวเลขสรุปอยู่ที่ `#/dashboard`

## ระบบทำอะไร

- เก็บว่าอุปกรณ์แต่ละเครื่องอยู่ที่ไหน เป็นของ Work Center ไหน สถานะอะไร และใครแก้อะไรไปเมื่อไหร่
- ติดตามงานซ่อม ตั้งแต่แจ้งเสีย รับเครื่องเข้าห้อง Setting Room ช่างรับงาน ซ่อมเสร็จ จนส่งเครื่องกลับที่เดิม
- นำเข้าและส่งออก Master sheet (CSV/XLSX) และตรวจนับอุปกรณ์รายเดือน

## ระบบเดิมมีปัญหาอะไร

ระบบเดิมเป็น PHP ประมาณ 6,000 บรรทัด ใช้มาตั้งแต่ราวปี 2019 และเพิ่มหน้าใหม่ไปเรื่อย ๆ ปัญหาที่เจอมีดังนี้

ความปลอดภัย
- นำค่าจากฟอร์มต่อเข้า SQL ตรง ๆ แทบทุกหน้า รวมถึงหน้า Login (`WHERE username = '$user' AND password = '$pwd'`) จึงโดน SQL injection ได้
- หน้า Login เช็คแค่ว่าคิวรีรันผ่าน ไม่ได้เช็คว่าเจอผู้ใช้ รหัสผิดก็มีโอกาสเข้าได้
- รหัสผ่านเก็บเป็นข้อความธรรมดา และหน้า Admin แสดงรหัสผ่านของทุกคนในตาราง
- ไม่มี CSRF token สิทธิ์ถูกจำกัดแค่การซ่อนเมนู
- รหัสฐานข้อมูลอยู่ในโค้ด และ error ของฐานข้อมูลขึ้นหน้าจอ (`or die(mysql_error())`)

เวอร์ชันของ PHP
- ใช้ฟังก์ชัน `mysql_*` ราว 60 จุด ฟังก์ชันชุดนี้ถูกถอดออกตั้งแต่ PHP 7 (2015) server จึงต้องอยู่บน PHP 5 ที่ไม่มี security patch แล้ว
- มี jQuery สองเวอร์ชัน และไฟล์สำรองอย่าง `BK_*.php`, `__index.php`, `sql_import_data_v01.php` ค้างอยู่บน server จริง

การใช้งาน
- ไม่มีระบบงานซ่อม "ซ่อม" เป็นแค่ค่าสถานะ ไม่รู้ว่าใครแจ้ง ใครรับ หรือรออะไหล่อยู่
- เครื่องที่ยกเข้าห้อง Setting Room ไม่ได้จำที่อยู่เดิมไว้ ซ่อมเสร็จแล้วต้องจำเองว่าต้องส่งคืนที่ไหน
- ไม่มีประวัติการแก้ไข (โค้ดบันทึก log มีอยู่แต่ถูกคอมเมนต์ไว้)
- ผู้ใช้หนึ่งคนผูกได้แผนกเดียว
- นำเข้า CSV แล้วข้อมูลที่ทีม IT แก้ไว้ถูกเขียนทับ และเปิดไฟล์ XLSX ไม่ได้

การดูแลโค้ด
- HTML, SQL และ logic อยู่ในไฟล์เดียวกัน
- ข้อความไทยและอังกฤษฝังอยู่ในโค้ด ชื่อสถานะเขียนซ้ำหลายที่และไม่ตรงกัน
- ไม่มีเอกสาร สคริปต์ติดตั้ง test หรือเครื่องมือย้ายข้อมูล

## ทำไมเขียนใหม่

ถ้าจะแก้ SQL injection และเลิกใช้ `mysql_*` ก็ต้องแก้แทบทุกไฟล์อยู่แล้ว ระบบงานซ่อมก็ต้องสร้างใหม่ทั้งหมด เลยเลือกเขียนใหม่ แล้วใช้สคริปต์ย้ายข้อมูลเดิมเข้ามา

| | ระบบเดิม | ระบบนี้ |
|---|---|---|
| SQL | ต่อสตริง | parameter ทุกคิวรี (Dapper) |
| รหัสผ่าน | ข้อความธรรมดา | BCrypt |
| สิทธิ์ | ซ่อนเมนู | API ตรวจทุก request, มี CSRF token ทุกการบันทึก |
| งานซ่อม | ไม่มี | Ticket: แจ้ง (ต้องมีเลข Flowlites) → รับเข้าห้อง → ช่างรับงาน → กำลังซ่อม / รออะไหล่ → เสร็จ → ส่งกลับที่เดิม |
| ห้อง Setting Room | กรอกเอง | โหมดสแกนรับเข้าและส่งออก ใช้เครื่องสแกนหรือพิมพ์ได้ |
| ประวัติ | ไม่มี | บันทึกทุกการแก้ไข |
| สิทธิ์ตามแผนก | 1 คน 1 แผนก | 1 คนหลาย Work Center |
| นำเข้า | CSV, เขียนทับ | CSV และ XLSX, ไม่ทับชื่อ Work Center ที่ Admin ตั้งไว้ |
| ภาษา | ปนในโค้ด | อังกฤษ สลับเป็นไทยได้ |
| Test | ไม่มี | xUnit |

ใช้ .NET Framework และ PostgreSQL เพราะเป็น stack เดียวกับระบบอื่นที่ทีมดูแลอยู่บน IIS หน้าเว็บ (HTML/JS/CSS) เป็นชุดเดียวกับรุ่น PHP ก่อนหน้า ผู้ใช้จึงไม่ต้องเรียนหน้าจอใหม่

## โครงสร้าง

```
Browser: Default.aspx + assets/js (SPA, Bootstrap 5)
   │  fetch JSON, session cookie + X-CSRF-Token
   ▼
api.ashx?r=<route> → Api/Kernel → Api/Controllers → Services → Repositories (Dapper) → PostgreSQL
```

- .NET Framework 4.8, C# 7.3, IIS หรือ IIS Express
- PostgreSQL ผ่าน Npgsql และ Dapper
- BCrypt.Net, Newtonsoft.Json, อ่านเขียนไฟล์ Excel เอง
- xUnit สำหรับ unit test (ไม่ต้องใช้ฐานข้อมูล)

ถ้า API ต่อฐานข้อมูลไม่ได้ จะตอบ `db_unavailable` แล้วหน้าเว็บจะเปลี่ยนไปใช้ข้อมูลตัวอย่างใน `assets/js/demo-api.js`

## Demo บน Vercel

Vercel รัน .NET Framework ไม่ได้ จึงขึ้นไปแค่หน้าเว็บ

- `tools/build-demo.js` แปลง `Default.aspx` เป็น `dist/index.html`, คัดลอก `assets/` และสร้าง `api-demo.json` ที่ตอบ `db_unavailable`
- `vercel.json` ส่งทุก request ของ `/api.ashx` ไปที่ไฟล์นั้น หน้าเว็บจึงเข้าโหมดข้อมูลตัวอย่างทันที

```bash
node tools/build-demo.js
vercel deploy --prod
```

## รันบนเครื่อง

1. เปิด `AssetCtrl.sln` ใน Visual Studio 2022 แล้วกด F5 หน้าเว็บจะเปิดที่ http://localhost:8471/ (ยังไม่มีฐานข้อมูลก็เปิดได้ จะเป็นโหมดข้อมูลตัวอย่าง)
2. คัดลอก `AssetCtrl.Web/ConnectionStrings.config.example` เป็น `ConnectionStrings.config` แล้วใส่ค่าฐานข้อมูล
3. รัน `AssetCtrl.Setup` เพื่อสร้างตารางและผู้ดูแลคนแรก
