## ระบบนี้คืออะไร

Asset Ctrl คือทะเบียนกลางของอุปกรณ์ IT ในโรงงาน ตอบได้ว่า **อุปกรณ์แต่ละเครื่องอยู่ที่ไหน เป็นของ Work Center ไหน สถานะอะไร และเคยเกิดอะไรขึ้นกับมัน**
และเชื่อมทะเบียนนั้นเข้ากับขั้นตอนการซ่อม ตั้งแต่แจ้งเสีย → รับเข้าห้อง Setting Room → ช่างซ่อม → ส่งกลับที่เดิม

Repo นี้คือรุ่นปัจจุบัน: **ASP.NET Web Forms (.NET Framework 4.8) + PostgreSQL** ที่เขียนขึ้นมาแทนระบบเดิม (PHP + MySQL) ซึ่งใช้งานมาตั้งแต่ราวปี 2019

## ปัญหาของระบบเดิม

ระบบเดิมเป็น PHP แบบหน้าต่อหน้า (~6,000 บรรทัด) ที่ต่อเติมมาเรื่อย ๆ หลายปี ปัญหาแบ่งได้เป็น 4 กลุ่ม

### 1. ความปลอดภัย — เสี่ยงสูง
- **SQL Injection เกือบทุกหน้า** — นำค่าจาก `$_POST` / `$_GET` ต่อเข้า SQL ตรง ๆ รวมถึงหน้า Login
  (`... WHERE username = '$user' AND password = '$pwd'`) เปิดทางให้ข้ามการล็อกอิน หรืออ่าน/ลบข้อมูลทั้งฐานได้
- **ตรวจรหัสผ่านผิดหลัก** — โค้ดเช็คแค่ว่าคิวรี "รันสำเร็จ" ไม่ได้เช็คว่า "เจอผู้ใช้" จึงมีโอกาสเข้าสู่ระบบได้แม้รหัสผิด
- **เก็บรหัสผ่านเป็นข้อความธรรมดา** และหน้า Admin **แสดงรหัสผ่านของผู้ใช้ทุกคนในตาราง**
- ไม่มี CSRF token, ไม่ตรวจสิทธิ์ฝั่ง server อย่างเป็นระบบ (ซ่อนแค่เมนู)
- รหัสฐานข้อมูลเขียนไว้ในโค้ด และ error ของฐานข้อมูลแสดงออกหน้าจอตรง ๆ (`or die(mysql_error())`)

### 2. เทคโนโลยีหมดอายุ — อัปเกรด server ไม่ได้
- ใช้ฟังก์ชัน `mysql_*` (ราว 60 จุด) ซึ่ง **ถูกถอดออกจาก PHP ตั้งแต่ PHP 7 (ปี 2015)**
  server จึงต้องค้างอยู่บน PHP 5 ที่ไม่ได้รับ security patch แล้ว อัปเกรดเมื่อไหร่ระบบล่มทันที
- jQuery หลายเวอร์ชันปนกัน และไฟล์สำรองแบบ `BK_*.php`, `_index.php`, `__index.php`, `sql_import_data_v01.php` ค้างอยู่บน production

### 3. ไม่ตอบโจทย์งานจริง
- **ไม่มีระบบงานซ่อม** — "ซ่อม" เป็นแค่ค่าสถานะหนึ่ง ไม่รู้ว่าใครแจ้ง ใครรับงาน ถึงขั้นไหน รออะไหล่หรือไม่
  เครื่องที่ยกมาห้อง Setting Room **ไม่มีการจำที่อยู่เดิม** ซ่อมเสร็จต้องจำเองว่าต้องส่งคืนที่ไหน → อุปกรณ์หลงหาย
- **ไม่มีประวัติการเปลี่ยนแปลง** — โค้ดบันทึก log มีอยู่แต่ถูกคอมเมนต์ปิดไว้ ใครแก้อะไร เมื่อไหร่ ย้อนดูไม่ได้
- สิทธิ์ผูกกับ "แผนก" ค่าเดียวต่อผู้ใช้ คนที่ดูแลหลาย Work Center ทำงานไม่ได้
- นำเข้า Master sheet (CSV) แล้ว **เขียนทับข้อมูลที่ทีม IT แก้ไว้** และไม่รองรับไฟล์ Excel (XLSX)
- ใช้กับเครื่องสแกนบาร์โค้ดได้ไม่ดี ต้องใช้เมาส์ช่วยหลายจังหวะ

### 4. ดูแลรักษายาก
- HTML + SQL + logic ปนอยู่ในไฟล์เดียวกัน แก้จุดหนึ่งกระทบอีกหลายหน้า
- ข้อความไทย/อังกฤษฝังในโค้ด, label สถานะกำหนดซ้ำหลายที่และไม่ตรงกัน
- ไม่มีเอกสาร ไม่มีสคริปต์ติดตั้ง ไม่มี test ไม่มีเครื่องมือย้ายข้อมูล

## ทำไมต้องปรับระบบ (แทนการไล่แก้ของเดิม)

ปัญหาอยู่ที่ **โครงสร้าง** — SQL ปนกับหน้าเว็บ, ใช้ API ที่ถูกถอดออกจากภาษาแล้ว, ไม่มีโมเดลของงานซ่อม
การไล่แก้ทีละหน้าต้องแตะแทบทุกไฟล์อยู่ดี จึงคุ้มกว่าที่จะเขียนใหม่บนโครงที่แยกส่วนชัดเจน แล้วย้ายข้อมูลเดิมมาด้วยสคริปต์

| | ระบบเดิม | Asset Ctrl (รุ่นนี้) |
|---|---|---|
| ความปลอดภัย | SQL ต่อสตริง, รหัสผ่าน plain text | Parameterized SQL ทุกคิวรี (Dapper), BCrypt, CSRF token ทุกการเขียน, API ตรวจสิทธิ์ทุก request (401/403/419/422) |
| แพลตฟอร์ม | ติดอยู่บน PHP 5 ที่หมดอายุ | .NET Framework 4.8 บน IIS (Windows Server) + PostgreSQL |
| งานซ่อม | ไม่มี | Ticket เต็มรูปแบบ: แจ้ง (บังคับเลข Flowlites) → รับเข้า Setting Room → ช่างรับงาน → กำลังซ่อม ⇄ รออะไหล่ → ซ่อมเสร็จ → ส่งคืน **ที่เดิมอัตโนมัติ** |
| ห้อง Setting Room | กรอกมือ | โหมดสแกน **รับเข้า (เขียว) / ส่งออก (ส้ม)** ใช้ได้ทั้งเครื่องสแกนและคีย์บอร์ด ไม่ต้องจับเมาส์ |
| ประวัติ | ไม่มี | บันทึกทุกการเปลี่ยนแปลง ใคร/อะไร/เมื่อไหร่ |
| สิทธิ์ | 1 ผู้ใช้ = 1 แผนก | 1 ผู้ใช้ = หลาย Work Center, Admin กับ User เห็นหน้าจอคนละแบบ |
| นำเข้า/ส่งออก | CSV, เขียนทับ | CSV + XLSX, อัปโหลดแบบแบ่งชิ้น, ไม่ทับชื่อที่ Admin ตั้งไว้, ส่งออกกลับเป็น layout เดิมได้ |
| ตรวจนับ | หน้าตรวจแยก | รอบตรวจนับรายเดือน เทียบกับทะเบียน |
| ภาษา | ปนกันในโค้ด | อังกฤษเป็นหลัก + สลับไทยได้ทั้งระบบ |
| คุณภาพโค้ด | ไม่มี test | xUnit unit tests (รหัสผ่าน, แบ่งหน้า, route, Excel/CSV …) |
| ติดตั้ง | ทำมือ | `AssetCtrl.Setup` สร้างตาราง ผู้ดูแลคนแรก และข้อมูลตัวอย่าง |

### ทำไมเลือก .NET + PostgreSQL
- **ใช้ stack เดียวกับระบบอื่นของทีม** (ASP.NET + PostgreSQL บน IIS) — ดูแล server, backup และโค้ดด้วยทักษะชุดเดียวกัน
- **Type-safe** — คอมไพเลอร์จับข้อผิดพลาดได้ก่อนขึ้นระบบ และมี unit test ครอบ logic สำคัญ
- **PostgreSQL เข้มงวดกว่า** — ไม่ยอมรับค่าผิดชนิดแบบเงียบ ๆ ข้อมูลในทะเบียนจึงสะอาดกว่า
- **หน้าเว็บชุดเดิม** — frontend (HTML/JS/CSS) เป็นชุดเดียวกับรุ่นก่อน ผู้ใช้ไม่ต้องเรียนใหม่ เปลี่ยนเฉพาะหลังบ้าน

## สถาปัตยกรรม

```
Browser (Default.aspx + assets/js/*.js — SPA, Bootstrap 5, ไม่มี build step)
        │  fetch() JSON · session cookie + X-CSRF-Token
        ▼
api.ashx?r=<route> → Api/Kernel → Api/Controllers → Services → Repositories (Dapper) → PostgreSQL
```

| ชั้น | ใช้อะไร |
|---|---|
| Runtime | .NET Framework 4.8, C# 7.3, IIS / IIS Express |
| หน้าเว็บ | `Default.aspx` (หน้าเปล่า) + SPA ใน `assets/` |
| API | `api.ashx?r=<route>` ตอบ `{ ok, data }` / `{ ok:false, errors }` พร้อม HTTP status ที่ถูกต้อง |
| ฐานข้อมูล | PostgreSQL, Npgsql, Dapper |
| อื่น ๆ | BCrypt.Net, Newtonsoft.Json, อ่าน/เขียน Excel เอง (ไม่ใช้ไลบรารี) |
| Test | xUnit (ไม่ต้องใช้ฐานข้อมูล) |

เมื่อต่อฐานข้อมูลไม่ได้ API จะตอบ `db_unavailable` แล้วเบราว์เซอร์สลับเป็น **Demo mode** (`assets/js/demo-api.js`) เอง

## Demo บน Vercel ทำงานอย่างไร

Vercel ไม่รัน .NET Framework / IIS จึง deploy เฉพาะฝั่งหน้าเว็บ:

- `tools/build-demo.js` แปลง `Default.aspx` เป็น `dist/index.html`, คัดลอก `assets/` และสร้าง `api-demo.json` ที่ตอบ `db_unavailable`
- `vercel.json` rewrite `/api.ashx` → `/api-demo.json` แอปจึงเข้า Demo mode ตั้งแต่โหลดหน้าแรก (เหมือนตอน server ต่อฐานข้อมูลไม่ได้)

```bash
node tools/build-demo.js   # ได้โฟลเดอร์ dist/
vercel deploy --prod
```

## รันบนเครื่อง (ของจริง)

1. เปิด `AssetCtrl.sln` ใน Visual Studio 2022 แล้วกด **F5** → http://localhost:8471/ (ยังไม่มีฐานข้อมูลก็เข้า Demo mode ได้)
2. ต่อ PostgreSQL: คัดลอก `AssetCtrl.Web/ConnectionStrings.config.example` เป็น `ConnectionStrings.config` แล้วใส่ค่าของตัวเอง
3. สร้างตาราง + ผู้ดูแลคนแรกด้วย `AssetCtrl.Setup`
